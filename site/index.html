Three video models, one prompt: Seedance 2.5, Kling VIDEO 4.0 and MiniMax H3 on Runware

We sent the same prompt to Seedance 2.5, Kling VIDEO 4.0 and MiniMax H3 through Runware's API in two scenes: a motocross POV from text alone, and a character sheet animated from one reference image. Each scene plays below with all three takes on one clock, under each clip what ffprobe measured on the file, what the run cost and how long it took.

Scene 2 · Character sheet to animation

One reference image, the same character sheet for all three, 10 seconds, 16:9. The sheet was made on Runware too, with GPT-Image-2.6. The prompt does not name the image with a model's reference tag; it says "this character sheet".

What each model exposes on Runware

Published facts come from each model's Runware schema and guides, read into the Model Arena spec database. Rows in green are measured on this post's six clips.

What we found

  • All six clips are 24 fps, and none of the three models publishes that. Seedance and Kling returned 241 frames for a 10 s request, 24 × 10 + 1. H3 returned 243 frames, 10.125 s.
  • The same resolution setting gave two frame sizes. Seedance and Kling came back at 1280×720, H3 at 1344×768, its 768p tier.
  • Kling and H3 billed exactly ten seconds at list price, $1.57 and $0.80. Seedance billed $2.3208 against $2.304 for ten seconds at $0.2304, on every Seedance run we made at this setting.
  • All three left the helmet camera for the backflip. Each shows the flip from trackside, then Kling and H3 return to the handlebar view. A flip seen from the helmet would roll the horizon through a full turn; no run so far has done it.
  • Each model names a reference image its own way: <<<image_1>>> on Kling, @Image1 on Seedance, "Image 1" on H3. The scene 2 prompt used none of them, and all three still made the same green-and-yellow vehicle, so the image was used without a tag.
  • A prompt that named a real brand was refused by the model vendor, and nothing was charged. Runware answers the task with HTTP 400 and the code invalidProviderContent. Read the task's errors when you poll, or a refused run looks like one that is still rendering.

Run it yourself

The scene 2 task for Seedance 2.5, as Runware's API takes it. Field names follow the Model Arena Runware provider (providers/runware-api/task.ts, poll.ts), checked against the model's schema.

const post = (tasks) => fetch("https://api.runware.ai/v1", {
  method: "POST",
  headers: { Authorization: `Bearer ${RUNWARE_API_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify(tasks),
}).then((r) => r.json());

const taskUUID = crypto.randomUUID();
await post([{
  taskType: "videoInference",
  taskUUID,
  model: "bytedance:seedance@2.5",
  positivePrompt: "animate this character sheet treating it as storyboard, …",
  inputs: { referenceImages: ["https://…/character-sheet.png"] }, // a URL, or a mediaUUID from a mediaStorage upload
  duration: 10,
  resolution: "720p",
  deliveryMethod: "async",
  includeCost: true,
}]);

// Poll by taskUUID. Never resubmit: that bills a second clip.
let row;
while (!row) {
  await new Promise((r) => setTimeout(r, 5000));
  const { data = [], errors = [] } = await post([{ taskType: "getResponse", taskUUID }]);
  if (errors.length) throw new Error(errors[0].message);
  row = data.find((d) => d.taskUUID === taskUUID && typeof d.videoURL === "string");
}
console.log(row.videoURL, row.cost); // cost in USD, from includeCost
